Fresh source-only feasibility acquisition v0.14
3 October 2026

Twelve HTML objects were collected once each from six deterministically selected
issuer groups. All twelve match their immutable released-object digests after an
explicit Git LFS digest reconciliation. This is a source collection and identity
check, not a benchmark, historical replay, source-fidelity certificate or result
for the proposed comparison-evidence method. No new QA or references were created.

The selection was frozen before source-body retrieval at repository revision
06387eff2b66def7a391f0bec8820b461339dd46 of
https://huggingface.co/datasets/Anonymous-Team-HC-RAG/Multi-doc-2025
Only original_doc filenames and object metadata were used to choose files.
The tree API returned all 179 source files without a pagination link. There are
89 distinct ticker prefixes (45 triples and 44 singletons), whereas the dataset
card reports 87 companies. This discrepancy remains explicit.

Prior source registers, discovery/frame inventories, identifiable public QA
previews and corporate aliases were screened. Nineteen ticker groups remained
with consecutive filename years in 2022–2024. The fixed seed and hash formulas,
all 89 eligibility records and the complete eligible order are preserved in
data/fresh_source_audit_v14/acquisition_protocol.json and exclusion_ledger.json.
Unidentified issuers appeared in earlier DocFinQA previews. Thus the exclusion
screen does not certify absolute absence of prior exposure. These are development
sources; none is called held out, and model pretraining exposure is uncontrolled.

The Berkshire files were retained with their original filenames and selection.
Their period-end fields are 2021-12-31 and 2022-12-31. They support a consecutive
source-internal annual-report relation but do not meet an actual-FY2022–2024
window. There was no replacement or relaxed window to force six eligible pairs.
The other five pairs have source-internal fiscal-year labels within that window.
This is an eligibility observation, not admission of five validated QA histories.

All twelve returned HTTP 200, totaling 62,730,877 bytes, below the 100 MiB total
and 20 MiB per-file caps. No retries, reserve selections or replacement documents
were used. Full HTML bytes remain outside the repository. Public files include
only source metadata, locators, hashes, receipts and reproduction code.

The first capture checker compared every downloaded object against a Git blob
OID and flagged the two Berkshire files. Their Git tree OIDs identify LFS pointer
blobs; the pre-download listing also contains LFS content SHA256 values. Offline
reconciliation confirms both downloaded SHA256 values equal those frozen LFS
values. The original checker and receipt remain unchanged; the separate
results/fresh_source_integrity_reconciliation_v14.json records this correction.
Ten ordinary Git objects and two LFS content objects now verify. This does not
independently authenticate original SEC bytes or document completeness.

Source-only checks identify a consistent CIK within each pair, Form 10-K and
successive reporting periods. Inline XBRL identity metadata is distinguished from
visible cover markup. All documents contain raw HTML tables and inline XBRL;
presentation tables, merged cells, hidden metadata and external assets still
need a source-faithful representation audit. Only HTML objects were acquired;
dependent images/assets were not rendered or verified. Embedded SEC exhibit
links do not identify or verify the current filing's original accession.

What remains unresolved

Original publisher/accession correspondence, first-public availability, source
completeness, extraction fidelity, comparable metric/scope bindings and actual
question sufficiency are unverified. Annual reports are not automatically
corrections of the same assertion. The present reviewer roles are model-assisted
and share project familiarity; they are not independent human gold annotators.
Underlying source redistribution rights are unresolved despite the dataset's
CC BY 4.0 label. Source originals therefore remain unbundled.

This six-group, one-attempt acquisition is the authorized concrete increment;
the earlier eight-group/two-attempt idea in fresh_history_evaluation_plan_v14.txt
remains a superseded immediate-action proposal. Its larger split, baseline,
annotation and numerical publication-investment thresholds remain proposals,
not executed tests or retroactive requirements satisfied by this collection.

The bounded next decision is whether a faithful source representation and
original-filing identity can be established for these captured objects. Only
after that decision should source-authored comparison questions and references
be considered. Neither corpus collection nor table counts justify a specialized
algorithm or a new benchmark claim.

Reproduction

scripts/freeze_fresh_source_cohort_v14.py reproduces selection from the pinned
source_listing.json and recorded exposure inputs. It refuses to overwrite frozen
artifacts. scripts/capture_fresh_sources_v14.py performs the bounded one-attempt
capture into an external directory and refuses existing receipts/source files.
Its initial Git-only status logic is intentionally preserved as executed.
scripts/audit_fresh_source_objects_v14.py verifies the correct Git/LFS digest
namespace and inventories whitelisted identity fields and raw structural counts
offline. It requires lxml (executed version 6.1.1) and also refuses overwrite.
Use fresh output paths for any reproduction; retain the initial and reconciled
receipts together. The summary result binds all exact artifact hashes.
