Reproducing v0.14: portable metadata, retained artifacts and new execution

Run commands from acl2027_temporal_state/. Python, NumPy and the declared package
versions are needed for relevant stages; PDF rendering additionally uses ReportLab
and the source HTML inventory uses lxml. Use fresh output paths. Never overwrite
frozen v13/v14 attempts or infer that new bytes/timestamps are the original run.
The results and limitations are summarized in docs/research_update_v14.txt.

1. Portable checks: no inference, raw sources or model weights

The default main-study verifier reads repository metadata only. It checks recorded
hash/count/schema/crosslink consistency; it does not recertify raw text, native
tokenization or answer semantics. It supports a relocated checkout. The retained
portable audit passed 1,348 checks in both the canonical and copied metadata tree.

  python3 scripts/verify_structured_study_v14.py --root .

  python3 scripts/summarize_structured_study_v14.py \
    --output results/structured_study_summary_v14.json --check

  PYTHONPATH=src python3 -m unittest discover -s tests -q

The completed full unit run passed 484 tests. The 14 authored witness scaffold
checks can also be run alone without source data or model inference:

  PYTHONPATH=src python3 -m unittest discover -s tests \
    -p test_witness_selection_v14.py -v

The main summary replays frozen public grades/projections, including all failures;
it does not regrade answers. --check compares exact deterministic output. It is
different from recomputing model predictions. The witness tests validate supplied
finite examples and bookkeeping, not a learned/automatic method or natural gain.

The following main audit still makes zero model calls, but additionally opens the

  python3 scripts/verify_structured_study_v14.py --external

Neither of these commands generates answers or reruns ONNX embeddings:

  python3 scripts/verify_dense_execution_v14.py --output NEW_DENSE_AUDIT_JSON

  python3 scripts/summarize_dense_source_support_v14.py --check

The first command mechanically replays rankings from saved vectors and retained
packing costs. Its default status leaves a fresh native recount pending. The

48 source-support records and fixed fact denominators, and exactly replays the
final summary. It rejects changed inputs and exposes conflicting duplicate grades
without silently adjudicating them. It evaluates source support, not QA accuracy.

To repeat the final 48-prompt tokenizer recount, choose a new external directory
and a new audit output. This opens one pinned native tokenizer session, makes zero
completions and requires the reader weight/runtime plus authorized host resource
access. It is not a portable metadata check:

  python3 scripts/verify_dense_execution_v14.py \
    --tokenize --tokenizer-dir NEW_EXTERNAL/dense_recount \

The retained recount audit passed 983 checks. It checked source spans, saved-vector

4. Reconstructing the dense source-only follow-up

data/dense_retrieval_v14/source_coverage_protocol.json freezes the exact six
conditions and forbids further natural QA in this stage. The completed run has
48 contexts: 16 exact BM25 controls and 32 newly reviewed dense/RRF contexts.
No result-based tuning or answer generation was performed. Detailed executable
commands, exact model/tokenizer/wheel hashes and dependency requirements are in
docs/dense_retrieval_feasibility_v14.txt.

Acquire/check public assets separately:

  python3 scripts/fetch_dense_assets_v14.py \
    --config configs/dense_retriever_candidate_v14.json \
    --assets NEW_EXTERNAL/dense_assets --download \
    --receipt NEW_DENSE_ASSET_RECEIPT

Install only the hash-verified pinned wheels in an isolated environment with the
declared existing versions. The sandbox ORT import failed on restricted CPU
telemetry; the same build imported and executed successfully on the authorized
host. Preserve both receipts. The root completion gate must bind the actual
completed 32-response main receipt, encoder/config hashes and retained failures.
Use fresh index/output paths for a new run. Set DENSE_PYTHON to the isolated
environment's Python executable; the commands are:

  "$DENSE_PYTHON" scripts/dense_retrieval_v14.py encode \
    --config configs/dense_retriever_candidate_v14.json \
    --manifest data/structured_reader_v14/corpus_manifest.json \
    --questions data/paired_reader_v13/questions.json \
    --assets NEW_EXTERNAL/dense_assets --execution-gate NEW_GATE_JSON \
    --output NEW_EXTERNAL/dense_index

  "$DENSE_PYTHON" scripts/run_dense_retrieval_v14.py \
    --index NEW_EXTERNAL/dense_index \
    --reader-config configs/structured_reader_main_v14.json \
    --tokenizer-artifacts NEW_EXTERNAL/dense_tokenizer \
    --contexts NEW_EXTERNAL/dense_contexts.jsonl \
    --metadata NEW_DENSE_RETRIEVAL_JSON --runtime-receipt NEW_PACKING_RECEIPT

Encoding and native packing run serially. The wrapper holds exactly one native tokenizer
session for all 48 contexts; it calls counter=bridge.count_prompt and makes zero
completions. Indexing, query encoding, ranking, packing and session overhead are
timed separately. Encoder-only right truncation is recorded; original reader
source spans are preserved. Source review is prepared with:

  python3 scripts/prepare_dense_support_v14.py \
    --contexts NEW_EXTERNAL/dense_contexts.jsonl \
    --metadata NEW_DENSE_RETRIEVAL_JSON \
    --baseline-contexts EXISTING_ACTIVE_V14_CONTEXTS_JSONL \
    --output-dir NEW_EXTERNAL/support_packets --manifest NEW_SUPPORT_MANIFEST

It stops if the 16 BM25 contexts/questions/scopes fail exact identity or are not
covered by the existing review. Reviewers receive unchanged frozen facts and
source contexts, never native answers or condition mappings. The summarizer CLI
accepts --retrieval, --support-manifest, --plug-review, --opera-review,
--baseline-support, --protocol, --packing-runtime and --output, plus --check.
All input hashes are bound; changed reproduction bindings require a new protocol,
not a claim that the old summary was regenerated unchanged.
