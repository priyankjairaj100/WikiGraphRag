Resource and scheduling policy

Renderer authored controls finish first; the all-12 Arelle run then owns one
exclusive heavy-process window; natural rendering follows. There is one Arelle
worker at a time, a 300-second source wall limit, a 2 GiB summed owned-group RSS
watchdog and at least 256 MiB free shared memory. The kernel memory.max remains
exactly 8 GiB. The pressure proxy is the intentionally overlapping sum of anon,
file_mapped, shmem, kernel, sock, file_dirty, file_writeback, unevictable and
swapcached. Every launch requires proxy + 2 GiB reserve < 7 GiB; continuation
requires proxy < 7 GiB and no new run-global oom/oom_kill event. Missing
telemetry, live zero/unobserved RSS or unconfirmed cleanup fails closed.

Every monitoring sample records actual cgroup total, all proxy components,
events and owned-group RSS externally; public results retain sampled peaks.
Sequential reads are non-atomic and polling can miss transient peaks. This is
not a hard per-process memory sandbox or an exact resident-memory estimate.
The former 7.25 GiB total-current soft limit is not claimed to be enforced.

Interpretation

incomplete recovered DTS, XBRL validation errors and numerical disagreement
remain separate outcomes. A clean outcome applies only to the stated Arelle
options. It establishes neither SEC original-byte identity, SEC filing-rule
