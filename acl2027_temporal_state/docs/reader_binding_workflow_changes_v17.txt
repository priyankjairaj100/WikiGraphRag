v17 pre-authoring ambiguity and leakage resolutions
Source-free design changes from the v16 draft; no natural question or prediction.
These choices remain subject to independent review and a future authoring freeze.

1. Scope ambiguity: v16 described 24 base questions plus controls and a smaller
   stage A, while the selected pool is revenue/duration focused. v17 covers only
   six single-source duration questions and six separately scoped two-source
   questions plus six controls.
   Instant/ambiguity stage B is not silently included or promised.

2. Source chronology: 'earlier' could be incorrectly read from filenames despite
   the recorded Berkshire identity discrepancy. S uses the first physical object
   in the frozen manifest; dates come only from reviewed internal source cards.

3. Outcome-conditioned authoring: v16 did not fully specify how candidate order,
   reviewer feedback and packet choice interact. All maximum24 candidates close
   before reference review; first fully admissible candidate wins, maximum two
   per slot; no reviewer-driven rewrite or third replacement. Every failure stays.

4. Answer-directed metadata: deriving a pack from a reference can accidentally
   give B1/B2 gold concept labels or remove competitors. v17 fixes complete source
   bundle closure and question-free metadata for ALL occurrences before authoring.
   Question-specific whole-bundle selection remains disclosed oracle preparation.

5. Completeness versus token cap: the original pool text/count limits do not
   establish that two complete tables plus all dependencies fit the native prompt.
   Both full arm prompts must tokenize <=6,144 with exact template; <=64 numeric
   occurrences includes unsupported duplicates and neighbor/dependency quantities.
   Any excess rejects the candidate, never licenses answer-row truncation.

6. Reviewer independence: 'fresh' is an operational context boundary, not a human
   annotation or training-independence claim. Preserve R1/R2 initial outputs and
   adjudication. Do not expose future questions/references to paper/native reviewers.
   Control reviewers first see only the masked view in fresh independent contexts,
   then inspect hidden originals; full-reference familiarity is not ignored.

7. Withholding leakage: deleting a header can leave the binding in source hash,
   year-bearing QName, source card, question, adjacent prose, duplicate occurrence
   or normalized base-unit value. Audit all routes and an explicit nonidentifiability
   argument. Preserve all occurrence quantity lexemes/values and other relations;
   binding-only date/year labels may be removed under the declared omission.
   Dual-role quantity/binding tokens cannot be removed; reject when they leak.
   At most four aspect attempts per S, priority source/period/unit/population;
   controls stay unfilled when none is valid. Masking is a mechanistic access view.

8. Refusal semantics: a fully specified question with absent support requires
   insufficient, whereas ambiguity in the question requires clarify. Stage A
   tests the former. Safe-but-wrong clarification is separate from control success.

9. Arm order mismatch: v16 prose required parity alternation but its native
   validator requires B1 then B2. v17 deliberately follows fixed adjacent B1/B2
   without modifying published v16 code; disclose latency/order confounding.
   No natural transport/repair retry is allowed, closing another count ambiguity.

10. Reference handling: the v16 native host opens references.json. Before v17
    natural execution, review strict noninterference of references with generation
    or provide a new reference-free path. Natural semantic grading remains a
    separate required scorer; existing support checks explicitly do not grade
    question meaning. This is a pending implementation/review gate, not a fix
    claimed by these documents.

11. Beam and answer claims: eight is a maximum, potentially impossible for full
    citations under768 output tokens. Report actual beam size and truncation.
    Joint recall requires one hypothesis containing all P claims; unioning
    inconsistent hypotheses is not success. Diagnostic B1 traces are separated
    from material user-facing answers; wrong quantities are not exempted by refusal.

12. Denominator and adequacy loopholes: every planned slot/condition/arm survives
    admission/execution failure. Joint answer denominator12, quantity-claim18,
    controls6 and total conditions18 are not interchangeable. The model gate
    requires B1 or B2 >=11/12 with >=1/2 per issuer, all6 correct insufficient and
    zero unsupported control answers. Silence/invalid output cannot pass safety
    as competence. B0-only success triggers residual-need analysis, not model-gate
    success. Incomplete subsets can be diagnosed but cannot pass adequacy.

13. Baseline interpretation: B0 remains the existing narrow exact-word/year
    filter; it is not a general semantic parser. B1 is the same-model structured
    mapper, B2 the direct counterpart. Both see canonical typed values, so this
    is machine-assisted selection/scope competence rather than visual reading.
    Shared caps and access do not imply identical actual compute or latency.

14. Feasibility and provenance: eight small authored controls do not establish
    natural semantic competence or maximum prompt feasibility. No model load,
    natural call, source admission, reference or freeze is invented here. Model
    role annotation costs are recorded separately from the36 reader request cap.
    Any later source/reference-informed implementation change starts a new
    development version and preserves these earlier outcomes.

15. Semantic grading blinding: arm-name removal cannot conceal distinctive B1/B2
    schemas or traces. Require one canonical final-action/quantity/scope/citation
    projection for all arms; exclude diagnostics and score B1 proposals separately.
    Freeze the projection on authored controls and disclose residual structural
    distinguishability. This is an explicit remaining scorer implementation gate.

16. Legacy identity-card leakage: source_card() copies DEI fields while dropping
    hidden/visibility flags. A source-free audit of the frozen inventory finds
    fiscal-year focus8/12 hidden, fiscal-period focus and CIK12/12, registrant2/12.
    Thus new author cards need actual visible cover/heading support for issuer,
    report type and report date, omitting unsupported optional fields. Additional
    identity witness blocks require a separate pre-author render supplement when
    outside the frozen101 population; keep both denominators. Neither copying
    hidden metadata nor removing its hiding style certifies source-visible dates.
