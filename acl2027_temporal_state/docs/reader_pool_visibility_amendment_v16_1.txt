Reader candidate pool v16.1: explicit visibility-only amendment
Prepared 2026-10-04. Post-inspection engineering amendment; not a new research
result, pristine prospective experiment, source admission or natural QA evaluation.

Preserved parent

The frozen v16 rule evaluated all 1,765 tables in the twelve fixed source objects,
found 16 eligible tables, selected 13/24 planned slots and left four physical
sources with no selected table. Preserve scripts/select_reader_pool_v16.py,
data/reader_binding_v16/question_pool_protocol.json and results/reader_pool_v16.json
unchanged. Its author/reviewer packets remain in reader_pool_attempt01. None of
that work is overwritten, relabeled as success or removed from future reports.

Two separately versioned post-selection descriptions followed. The predicate
replay found 29 revenue-row leaf candidates that failed only the recognized
hiding-cue condition. The second characterization evaluated their 573 cue-bearing
subtrees and found no non-whitespace text, numeric facts, images/media, alt text,
label-bearing attributes, unknown nonempty attributes, nonlayout elements, inline
style content/url constructs or id/class hooks. The cue subtrees were 569 empty
cells and four whitespace-only rows. These counts motivated this amendment;
they are explicitly post-inspection evidence, not a claim of browser visibility
or proof that all possible hiding cases are harmless. Bind both descriptions:
results/reader_pool_failure_analysis_v16.json and
results/reader_pool_visibility_characterization_v16.json.

Authorized change

Only the recognized-hiding predicate changes. A recognized cue may be permitted
only when it is on a strict descendant of the candidate table and EVERY recognized
cue-bearing subtree passes the conservative empty-layout characterization. A cue
on the table or any ancestor remains a rejection. Mixed empty and nonempty cues
remain a rejection. All unsupported/uncertain cues remain a rejection.

Reuse the frozen characterize_reader_pool_visibility_v16.characterize_subtree
profile, which requires no non-whitespace subtree text, numeric fact markup,
images/media, alt/label-bearing attributes, unknown nonempty attributes,
nonlayout elements or inline style content/url construct. Unicode whitespace,
including NBSP, may count empty; zero-width non-whitespace characters do not.
Descendant text and tails are included; the cue node's own following tail is
outside its subtree. Comment/processing-instruction text is not displayed text.

Add one conservative restriction: the presence of an id or class attribute on
ANY element in the cue-bearing subtree blocks permission, including an empty
attribute. This is stronger than merely counting nonempty hooks in the descriptive
analysis. It avoids treating an empty hook as evidence that CSS cannot target
that node. Unknown or external stylesheet behavior and computed CSS remain
unverified even after this restriction. Actual per-block rendering review is
still required before question/evidence admission.

Everything else is identical to v16: the same twelve physical sources/order and
hashes, same leaf-table/complete-row-cell requirements, 4-32 total numeric
occurrences, at least four usable duration facts, at least two declared duration
period bindings, same revenue-row regex, same 12,000-character text cap, same first
two eligible XML-order tables per source, and the same 25,000,000-byte aggregate
external-output budget. Nil/unsupported facts still count in the table population
and remain in the selected packet. The amendment makes no numeric, binding,
source-year, period, table-text, row/cell or financial interpretation change.

No source rewriting

Do not remove, collapse or hide any original row/cell in the saved source view.
The author packet is generated by the unchanged v16 author_packet helper. The
reviewer packet retains the entire original table view, all joined typed facts,
visibility metadata and ancestor source wrappers. The amendment changes only
whether a table is eligible for the pool; it does not create a new rendered table
or assert that an importer's treatment of hidden empty columns is faithful.

The deterministic first-two rule can replace some originally selected tables
with earlier XML-order candidates. Record original selected ordinals retained
and displaced as descriptive counts; preserve every original packet. Neither
all-twelve-source coverage nor all24 slots is guaranteed. Unfilled slots, failed
sources and any remaining rejection categories are reported without further
threshold changes. A successful candidate pool is not yet an admitted question,
complete evidence pack, reference label or competent-reader result.

The public result contains counts, source identities, selection ordinals, gate
