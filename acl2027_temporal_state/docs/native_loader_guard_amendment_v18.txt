Kernel basis and limitation

Primary source: https://docs.kernel.org/admin-guide/cgroup-v2.html
Sections memory.max, memory.events, memory.current, memory.stat; accessed
2026-10-04. memory.max invokes OOM handling if boundary usage cannot be reduced;
temporary excess is possible. The max event counts impending boundary crossings
and differs from oom and oom_kill. Some failed allocations do not produce an oom
event. Therefore total-boundary observation alone does not establish exhausted
reclaim or required reader memory. No current resource polling underlies this
proposal. File-cache pressure is plausible in the historical partial load, not
demonstrated to explain it completely.

Exact changed behavior

scripts/native_loader_v18.py retains the v17 execution implementation with a
separate small guard adapter scripts/native_loader_guard_v18.py and profile
configs/native_loader_v18.json. memory.current >= memory.max is recorded in each
snapshot as total_boundary_observed; it alone no longer stops admission/loading.
memory.events:max is required, parsed as a nonnegative integer and retained in
the same snapshot. Its increase alone is diagnostic. Missing, malformed,
negative, duplicate, or reset event counters fail closed. max, oom and oom_kill
are compared against each immediately preceding accepted sample, including
pre-asset and prelaunch observations. Sampling is serialized only around the
resource check; an HTTP call never holds that lock. Any new oom/oom_kill still
stops. Historical nonzero counters at the first sample are not new events.

The snapshot files are consecutive reads, not an atomic kernel transaction.
Counters could reset and surpass their prior values between samples without
detection. A sampled watchdog is not kernel isolation. No memory.high/max writes,
counter resets, peer-process signals, or unrelated cache manipulation are made.

Risk and interpretation

The proxy deliberately overlaps categories and omits some charges. Neither its
admission allowance nor owned RSS reserves kernel capacity. RSS does not cover
every shared-cgroup charge, and peers may grow between observations. The shared
8 GiB kernel limit is not per-project containment: an OOM can select a peer
before our reactive event stop responds. Avoiding equality-triggered termination
accepts that additional risk; unchanged numerical limits do not erase it.

The historical partial load did not measure full residency, graph workspace,
actual KV/recurrent allocation, or reclaim latency. Static named-cache estimates
remain estimates. Even a successful new loader/tokenizer outcome establishes
only that bounded operation under its recorded conditions, not generation fit,
interface competence, natural QA improvement, a stronger reader, or publication
readiness. Authored completion and natural evidence gates remain separate.
