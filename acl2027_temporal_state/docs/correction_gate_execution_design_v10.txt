Correction gate execution design v0.10

Decision and limits

The unchanged core can demonstrate conditional withdrawal of source-grounded
atomic assertion records. It cannot answer general scientific/numeric questions.
Question.event_time is mandatory; TemporalClaim is an interval representation,
not a timeless fact type. Unknown endpoints mean unknown validity, not permanent
truth. With no source-supported observation or interval, even a sole positive
claim remains indeterminate. Never manufacture event intervals, observations,
actual outcomes, or historical prefixes to make this gate run.

This audit reads the frozen admission protocol and v09 route decision, core
implementation, existing source demo, and relevant tests; it does not inspect
new discovery artifacts, execute models, or establish any natural result.

What existing functions provide

corrections.validate_correction_policy checks IDs, exact source slices, authority
records, certificate/link offsets, chronology and acyclic essential dependencies.
materialize_corrected_selection accepts an explicitly selected reading/link state,
withdraws correction targets, propagates essential-support inactivity, preserves
original records in correction_ledger, and materializes survivors without adding
event dates. Cross-key dependency withdrawal is supported. Exact spans and hashes
do not establish authority attribution, replacement entailment, or dependence.

make_correction_state_semantics supplies the shared decoder hook.
correction_io.make_correction_cache/load_correction_cache bind a question-free base
and policy. correction_pipeline.decode_correction_cache runs independent,
iterative, iterative_restarts, or joint_exact on supplied scores. The independent
method still optimizes conditional links; it is not a full-source reader. Exact
optimization certifies only this bounded candidate objective, not factual truth.
Defaults are eight mentions, five readings per mention, and 250,000 conservative
states. Inactive assertions/link scores remain in the historical-interpretation
objective; it is not active-answer utility.

answer_corrected delegates to representation_io.answer_question, lexical routing
to one factual key, then CoupledMemory.answer_key. Definite answering requires
certain membership at the requested event date. There is no atomic/report-only
lookup, numerical recomputation, general entailment, or support-status QA API.
reported_actual excludes announced_future; announced_schedule still requires
temporal certainty. Scope strings such as a fiscal year do not create bounds.

Minimal runnable mechanism comparison, after source adjudication

Freeze one supplied source bundle and four genuinely sourced roles: original
assertion O, replacement R, downstream assertion D, and unaffected control U.
These are role names, not invented natural data. Bind exact claim/mention IDs,
source hashes, spans and the source-grounded essential edge D -> O. Preserve
literal values, units, scope, modality, unknown bounds and reporting provenance.
If the source does not supply these roles, stop that case before replay.

Call materialize_corrected_selection directly three times, with identical selected
readings and source records:
1. No withdrawal: no certificates/dependencies and null correction links.
2. Direct: source authorities and replacement certificate; select R CORRECTS O;
   no support dependencies.
3. Dependency: same direct state plus the adjudicated D -> O dependency.

Expected policy contracts, conditional on those declarations: O/R/D/U stay active
in (1); O is inactive in (2); O and D are inactive in (3); R and U survive all
three. Report actual ledgers, reasons, surviving records, and preserved bounds.
The no-withdrawal link intervention must be explicit: identical selected links
cannot both select a correction and disable its withdrawal under current semantics.
Mandatory numeric fields may be neutral 0.0 schema placeholders, unused by this
explicit-selection replay; never optimize them or call them natural/model scores.
This is an annotated policy-materialization illustration, not predicted QA or a
search-method win. run_correction_source_demo.py already makes this distinction,
but uses authored 10/0/2 preferences and has no downstream claim; do not relabel
that demo as this gate's evidence.

Unsupported or exclusion-sensitive cases

CORRECTS requires exactly the same normalized entity/relation/scope, same declared
asserting authority, replacement-to-target direction, and an explicit reference.
Only whole-assertion replacement is supported. Pure retraction, partial-field
editing, changed measurement time/scope, and reversal of a correction notice are
unsupported. Do not hide these differences in a generic value string. A scalar
is admissibly atomic only if independently meaningful in the source.

SupportDependency evidence must be in the dependent assertion's own source.
Every declared prerequisite is essential (AND); a missing selected prerequisite
also withdraws the dependent. There are no OR alternatives, weights, probabilistic
dependence, or automatic recomputation after a premise changes. A conclusion with
alternative independent support cannot be represented by asserting a false
essential edge. Separate sourced assertion records may survive independently,
but the core cannot certify their semantic equivalence. RESTATES is episode
identity, not copying or independent corroboration. No ancestor resurrection or
latest-correction winner is inferred. Authority is source-level: mixed speakers
need explicitly mapped attribution units, not domain-name authority guesses.
Inactive means this support was withdrawn, not that the conclusion is false or
that its corrected numerical value has been computed.

Same-source reader and eventual predicted comparison

A pinned full-prefix reader must consume the same frozen eligible source bytes
and fixed downstream/control questions, with no candidates, policy annotations,
scores, reference answers or decoder outputs. If an excerpt projection is used,
every method receives it and the claim is restricted to that projection; a
full-source reader comparison requires full-source delivery to both pipelines.
Freeze source/version/capture and request hashes, source order, prompt/schema,
model and runtime revisions, context/token limits, decoding settings, raw response
bytes, exact evidence offsets, abstentions and validation failures. Preserve
truncation/access failures instead of silently dropping evidence. Reader and
reference adjudication must be separate runs. The existing v08 source-reference
validator checks structure/spans, not truth, and is not a pinned reader runner.

For a scored method test, collect actual source-only candidates, correction policy
and scores with raw receipts after eligibility freeze. Use the same base cache,
aliases, objective, limits and seeds across four decoders; vary only the declared
withdrawal policy. No-withdrawal can omit certificates/dependencies, making CORRECTS
ineligible without hiding source text. Compare history-level downstream success
AND unaffected retention against direct withdrawal and the strongest reader/
iterative baseline using separately frozen references. Report extraction/scoring
failures and unresolved histories, not merely successful decodes.

Current-document-only cases remain labelled mechanism illustrations; quoted prior
wording is not an earlier capture. Paired prefixes require actual versions and
separately qualified availability evidence. Natural non-temporal QA needs a new,
explicitly specified atomic answering/evaluation adapter before comparison; that
is outside this unchanged-core gate. Without runnable comparable predictions,
record not executed, not a pass or an empirical failure of the v09 hypothesis.

Post-discovery clarification, 3 October 2026
The four-role expected pattern above is conditional on the dependent D lacking
its own explicit direct replacement. It is not the expected pattern for every
admitted correction. If a source also corrects D, include that replacement E and
its direct edge in both withdrawal arms. The v0.10 financial illustrations use
five roles and both direct edges; direct and dependency arms both retain R/E/U.
This clarification supersedes any unconditional reading of the generic pattern.
