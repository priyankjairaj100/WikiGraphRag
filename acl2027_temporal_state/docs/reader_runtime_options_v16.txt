Bounded comparison of options

The machine imposes a 3.8 GiB weight-file allowance and a 150 MiB runtime
allowance. Exact current metadata for the following files and alternatives is
in results/reader_runtime_feasibility_v16.json.

* Qwen3.5-9B UD-IQ3_XXS fits and is recommended for one trial. It uses most of
  the available weight allowance, so simultaneous models are excluded.
* Qwen3.5-9B UD-IQ2_M has 3,649,365,216 bytes. It leaves more room but lowers
  precision further. It is not an outcome-triggered fallback.
* Qwen3-8B Q3_K_S has 3,769,612,096 bytes. It is a distinct older checkpoint
  with a different attention architecture; fitting does not establish better
  reading. It was not selected for this proposed single-candidate trial.
* Qwen3.5-4B Q6_K has 3,525,956,768 bytes. It increases quantization precision
  relative to v14 but retains the same nominal model capacity. The evidence
  does not show quantization caused the v14 failures.
* Official Qwen3-8B Q4_K_M and Unsloth Qwen3.5-9B Q4_K_M exceed the weight
  allowance. They are not feasible downloads in this workspace allocation.

These are engineering choices, not an exhaustive model leaderboard. The v14
negative reader result stays intact; this proposal begins a new reader recipe.

Resource accounting matters on this machine

The host reports about 9.7 GiB of RAM, but the actual process cgroup remains
8,589,934,592 bytes. At the executable probe, memory.current was 2,464,219,136
bytes and /dev/shm had 4,707,643,392 bytes available. After storing the selected
weight, that snapshot leaves 691,407,648 bytes of /dev/shm space. This is enough
for a 512 MiB record reserve, but the checks must run again immediately before
acquisition because concurrent work changes both figures.

The 5.5 GiB per-process address-space limit leaves 1,889,344,288 bytes beyond
the selected weight for libraries, tokenizer, KV/state and computation buffers.
This arithmetic is not a prediction of peak memory or an OOM guarantee. A
full-context native preflight must measure the actual peak before natural runs.

Use a single streaming temporary weight file and atomic rename after checking
the exact count and SHA256. No Hugging Face cache copy, duplicate final copy,
or simultaneous alternate model should be created. Stream bounded blocks;
require HTTPS, exact length, finite socket/wall time and sufficient free space.
The proposal reserves at least 512 MiB of /dev/shm after the download and stops
acquisition at 7 GiB memory.current. Preserve a failed-attempt metadata receipt
before reclaiming an incomplete, unusable partial file.

For inference, preserve the 5.5 GiB address-space cap, 7 GiB active-memory
watchdog, 3600 CPU-second and 1050 wall-second process limits, 90-second startup
deadline, and 900-second request limit. Add a memory.current stop at 7.25 GiB,
polled independently every 0.1 seconds. The old active metric alone can miss
unmapped tmpfs contents during acquisition; tmpfs weights consume cgroup memory
even before the model maps them. Do not raise a guard automatically when a load
fails. Retain failures, measured peaks, timing and attempted recipe identities.

Remote inference is not ready evidence

The Hugging Face primary metadata endpoint lists Together, Featherless,
OVHcloud and DeepInfra as live providers for the upstream Qwen3.5-9B model.
That establishes advertised service availability only. The currently exposed
Hugging Face tools include Jobs and metadata access, but no direct completion
tool. The current credential advertises Jobs/read scopes rather than inference
permission. No account credits, free quota, provider access, endpoint version or
cost was verified. No remote completion or paid job was launched. Remote
inference therefore cannot be represented as an available executed baseline.
