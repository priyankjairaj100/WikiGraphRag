v0.8 current source capture and deterministic extraction

All 39 exact primary URLs in the previously frozen 19-history v0.7 frame were attempted, without substitutions. The frame itself remains unchanged. The first bounded run could not connect to the configured browser proxy inside the sandbox: all 39 requests returned curl exit 7, no response bytes. Its manifest and executed script are preserved. A network-authorized second run requested the same 39 URLs and completed all transfers. These are 78 HTTP attempts including the initial connection failures, not 78 source documents.

The final 39 responses contain 34 HTTP 200 and five HTTP 403. Two HTTP 200 responses from IBM are literal 195-byte Site Unavailable pages and are rejected. The five HTTP 403 responses are the first Amazon source, both Starbucks sources, and both Costco sources. Thus 32 sources pass provisional content checks and 15 of 19 histories have all listed sources provisionally available. Source usability is a collection check, not benchmark admission or semantic correctness. No challenge was bypassed, no login attempted, and no replacement URL selected.

The capture policy is four parallel transfers at most, 30 seconds total curl timeout, 10-second connection timeout, 8 MiB maximum response, five redirects maximum, HTTPS-only including redirects, one unauthenticated request per URL in each run, and no automatic retry. Exact URL, final URL, response status/type, transfer timing, response/header/text byte hashes, runtime versions, and start/end UTC timestamps are recorded. Source IDs are retained from the frame; source ID plus raw SHA256 identifies a frozen response. HTTP transfer completion is the retrieval timestamp. Displayed publication and update dates are copied from the discovery frame with their original basis. They are not independently certified historical first-publication times. Event-time annotation remains separate.

The executed retrieval code is preserved as data/source_stream_v08/executed_capture_v1.py.txt. Its SHA256 remains the capture_script_sha256 in the final manifest. The first extractor discarded all form elements. Three investor-news pages used an ASP.NET form to wrap their whole article, producing empty text even though exact response bytes contained the article. We repaired the extractor globally to retain visible form text; we did not change captured bytes or repeat network requests. The same repair explicitly recognizes the observed Site Unavailable page title. The repair changed 19 HTML text hashes and restored the three investor articles. The original manifest, every original response/header, prior extracted text, and prior per-source receipt are preserved. The final manifest binds the executed retrieval script, original manifest, repair script, updated extractor, and each before/after text hash.

HTML extraction uses Python's standard HTMLParser, excludes scripts, styles, noscript, SVG, navigation, footer and template text, retains body text, converts entities, normalizes Unicode to NFC, collapses whitespace within block-separated nonempty lines and writes UTF-8 with LF. It is a generic visible-document extraction, not an article detector. It can retain cookie notices, global banners, related-content cards and other page text. Chrome's undated global notice and Docker's later related cards must remain part of the supplied current document representation unless a distinct predeclared article-extraction condition is introduced. Do not reinterpret page chrome as a dated article claim. HTML title and bounded date/title/license metadata are retained separately. PDFs use the installed pdftotext reading order, UTF-8 output, NFC and the same nonempty-line normalization. Tool versions and exact extraction recipes are recorded.

Provisional usability requires HTTP 200, at least 80 extracted words, no recognized blocking/error-page title or challenge signal, and at least 0.6 lexical coverage of the expected title in the page title plus the first 12,000 extracted characters. Short documents and replacement characters are flagged. These checks detect obvious fetch failures; they do not prove article completeness, entailment, source authority or correct dates. The independent frame audit performs separate source-context review. Blocked responses and their hashes remain in the collection.

Full raw external responses, HTTP headers and extracted documents are stored outside the distributable project at /workspace/scratch/bdef663e3dfc/tmp/source_stream_v08/fulltext/{source_id}/. The project contains capture receipts, hashes, metadata and derivation information, not redistributed full external texts. The two GOV.UK responses visibly state an Open Government Licence notice, whose document-specific scope still requires review. Other permission is not inferred from public access. License uncertainty is reported, not converted to a reuse permission.
