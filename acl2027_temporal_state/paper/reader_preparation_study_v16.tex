\section*{Abstract}
Exact numeric decoding does not establish that a system selected the correct report, period, entity or population. This development checkpoint prepares the evidence and interface needed to test that distinction. A lossless storage amendment completes table extraction after a retained output-cap failure. The original fixed selection fills 13 of 24 planned table slots. A post-inspection visibility amendment fills 21 slots and covers all twelve filings, while retaining three unfilled slots and the original outcome. An acquired-only binding interface passes 71 authored checks after documented fixes. The native reader gate stops before model launch. These are preparation outcomes, not natural question-answering gains, retrieval improvements or a new algorithm. Amended taxonomy and source-render outcomes remain draft fields until their records are terminal.
\section*{1. What this checkpoint establishes}
The research objective remains an automatic reader that can interpret a separately written request and select every required source binding. The previous typed numeric work supplied exact values at explicitly provided aspects; it did not solve that mapping problem. This checkpoint therefore builds source views, a bounded candidate pool and a common acquired-evidence interface before attempting a new retrieval policy.

All physical sources are the same known development filings. Table and question selection can be informed by source review, but that makes the eventual experiment an oracle-evidence competence diagnostic. It must not be described as retrieval success or held-out generalization. The draft protocol separates deterministic lexical filtering (B0), a model proposer with deterministic typed rendering (B1), and a direct model reader (B2).

\section*{2. Complete structural views, with the failed attempt retained}
The first extraction hits its fixed storage cap and completes nine of twelve sources; three source failures, partial outputs and hashes remain recorded. A separate amendment changes storage to gzip without changing extraction logic. It completes the cohort and preserves the earlier output through a lossless compressed archive. Neither compression nor successful serialization repairs the original failed execution.

The views retain complete table rows and cells, captions, neighboring paragraph references, declared spans, source anchors, numeric occurrence links and recognized hiding cues. The extraction records DOM ownership rather than a browser-computed cell grid. It does not establish visual alignment, CSS visibility, semantic header attachment or complete supporting footnotes.

\section*{3. A retained coverage gap and a visibility-only amendment}
The original selection is deliberately narrow: leaf tables, complete row/cell ownership, no recognized hiding cue, a bounded numeric occurrence count, multiple resolved duration periods, a revenue or net-sales phrase within one row, and a bounded complete DOM text length. Nil, unsupported and invalid occurrences remain in the occurrence count. Binding-resolved period presence is separate from numeric usability.

The original rule selects tables from only part of the source cohort. A descriptive replay identifies candidates rejected solely because recognized hiding cues occur on empty layout subtrees. A separately frozen amendment permits such cues only on strict descendants meeting conservative emptiness checks; cues on the table or an ancestor, content-bearing subtrees and id/class hooks remain blocked. No row, value or source is removed or rewritten, and every nonvisibility predicate is replayed against the parent outcome.

\section*{4. Acquired-only binding and a common evidence budget}
The adapter stores only an immutable acquired evidence pack. Each fact has an opaque occurrence handle, its exact value or null, visible labels, and six explicit bindings: concept, entity, period, unit, population and physical source. Each available binding cites observed witnesses; an unavailable binding remains null. The adapter has no full-document callback or hidden-source lookup. Pack construction must still remove every duplicate disclosure of withheld evidence from visible text and labels.

B1 proposes a bounded beam of joint claim assignments and declares unresolved interpretation explicitly. The finalizer scans all exposed compatible occurrences, coalesces equal scoped quantities while retaining every occurrence and witness, and blocks unsupported or conflicting possible matches. Equal values in different years, units, entities or source versions remain distinct scoped claims. A compact shared-registry projection is lossless and identical for B1 and B2; unused registry content is rejected rather than silently discarded.

B0 uses fixed token overlap and witnessed constraints, with no question-specific mappings. B2 uses the same evidence and supplies quantities directly. Wrong canonical quantities remain in its output and are graded; a refusal prefix does not exempt a material claim. Syntax and exposed support do not certify that an answer satisfies the question.

\section*{5. Execution gates and scope of evidence}
Dependency capture records 117 resources and one transport timeout, leaving eleven complete source closures. Original validation launches no worker. A separate small-process amendment replaces the total-current soft cap with a conservative pressure proxy and reserve under the same kernel hard limit; it does not satisfy the old cap. That attempt fails on all sources: mixed physical/logical DOM traversal prevents completed inventories, and namespace PID lookup makes its RSS reports unreliable. No RSS-enforcement claim is made for that attempt. A separately reviewed repair preserves source bytes, comparison logic and processor options.

The pinned Qwen3.5-9B UD-IQ3\_XXS candidate was acquired with its exact file hash, but its authored native gate stopped before launch because observed total memory exceeded the unchanged guard. The receipt labels this tokenization\_failed; the follow-up review establishes that no model process, prompt tokenization or completion occurred. This is a feasibility failure, not a reading error, and it supplies no stronger-reader evidence. No retry or guard relaxation was made within this attempt.

Processor completion, numeric agreement and source identity are separate claims. Candidate taxonomy metadata does not establish original SEC byte identity; pinned options exclude SEC filing-rule, calculation and unit-registry checks. Rendering likewise requires actual visual/CSS review before source admission.

\section*{6. Research decision and reproducibility}
This checkpoint does not yet justify spending the next experiment on a novel retrieval policy. The necessary intermediate result is evidence that an automatic reader can correctly bind separately authored requests when complete evidence is already supplied. That requires reviewed visible source support, frozen question/reference sets, valid missing-evidence controls, and complete accounting of planned cells.

Both pool outcomes remain part of the record: the original source-coverage gap and the amended cohort coverage with residual empty table slots. The amendment does not establish that a question can be answered from each selected block. Later question/evidence admission must inspect actual visible dependencies. Reader tuning must likewise preserve the first result and record a revised model, prompt or interface as a new attempt.

The common interface provides a concrete engineering foundation for testing retrieval later. It distinguishes missing binding evidence from question ambiguity and preserves exact scoped alternatives. Those distinctions are conventional prerequisites. They become a research contribution only if an independently designed method improves a meaningful task under matched source access, reader strength and full cost accounting.
